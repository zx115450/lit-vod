## 一、写在前面

### 1.1 为什么要两个项目配合

| 项目 | 职责 | 不做什么 |
| --- | --- | --- |
| **Lite VOD**（video） | 视频对象存储、FFmpeg 转 HLS、媒资元数据、`fileId`、播放签名 | 用户体系、订单、图书架位、笔记 |
| **smart_bookstore** | JWT 登录、图书/借阅/订单、业务页、AI 客服与阅读 Agent | 视频二进制存储、转码 Worker |

类比已有文档 [对接天机学堂](../05-分步实现指南/16-增强与对接天机学堂.md)：`tj-media` 做课表鉴权，Lite VOD 做存储与播放。**书城扮演 `tj-media` 的业务层角色**。

### 1.2 典型业务场景

| 场景 | 说明 |
| --- | --- |
| 图书导读视频 | 《Redis 设计与实现》5 分钟导读，绑 `book_id` |
| 电子书配套课 | 规划中的 `ebook_id` + 章节精讲（与书城 `docs/AI阅读笔记模块分步实现指南.md` 联动） |
| 试看 | 未借阅：Lite VOD `exper=300`（前 5 分钟）或二期 `preview.m3u8` |
| 解锁 | 借阅中 `borrow_order` 或已支付 `trade_order` → 书城签发完整播放 |

### 1.3 MVP 演示目标

1. 管理端在 Lite VOD 上传 mp4，转码完成后得到 `fileId`
2. 书城管理端为某本书填写 `media_file_id`，保存关联
3. 用户打开图书详情 → 点击「配套视频」→ 试看可播
4. 模拟借阅成功后 → 同一入口可播完整视频
5. Postman 验证：无权限时 Lite VOD 只返回带 `exper` 的 `playUrl`

## 二、总体架构

```text
┌─────────────────────────────────────────────────────────────────┐
│                     smart_bookstore (8081)                       │
│  BookController / Borrow / Trade / Auth(JWT)                     │
│  BookMediaController（新建）→ 鉴权 → 调 Lite VOD 播放签名          │
│  book_media_ref 表：book_id ↔ fileId, preview_seconds            │
└────────────────────────────┬────────────────────────────────────┘
                             │ HTTP（内网）
                             │ GET /vod/signature/play?fileId=&exper=
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                     Lite VOD vod-api (8080)                      │
│  上传凭证 / 媒资落库 / 转码任务 / 播放 HMAC 签名                   │
│  media 表：fileId, media_url, status, duration                   │
└────────────┬───────────────────────────────┬────────────────────┘
             │                               │
             ▼                               ▼
      ┌─────────────┐                 ┌─────────────┐
      │   MinIO     │                 │  RabbitMQ   │
      │ raw/ hls/   │                 │  → Worker   │
      └──────┬──────┘                 └─────────────┘
             │ 签名 URL 反代
             ▼
      ┌─────────────┐
      │   Nginx     │  ← 浏览器 hls.js 拉 m3u8 / ts
      └─────────────┘
```

**数据流（播放）**：

```text
用户点击播放
  → 书城 GET /api/books/{id}/media/play（带 JWT）
  → 书城查 book_media_ref.file_id
  → 书城查用户是否借阅/购书 → 决定 exper（试看秒数）或 null（完整）
  → 书城服务端调 Lite VOD GET /vod/signature/play
  → 返回 playUrl 给前端
  → hls.js 向 Nginx 拉流（带 sign、e、exper）
```

**密钥**：`VOD_PLAY_SECRET` 仅 Lite VOD + Nginx 持有；书城通过 **服务端** 调 VOD 接口，不要把 Secret 下发给浏览器。

## 四、M0：双端环境与 HTTP 客户端（第 1 天）

**目标**：书城后端能根据 `fileId` 查询 Lite VOD 媒资信息（不播放）。

### Step M0.1 网络与端口

| 服务 | 默认端口 | 说明 |
| --- | --- | --- |
| smart_bookstore | 8081 | 业务 API |
| lite-vod-api | 8080 | 媒资与签名 |
| MinIO | 9000 | 对象存储 |
| Nginx 播放 | 8088 等 | 以 `nginx/conf.d` 为准 |

```text
□ docker compose -f lite-vod/docker-compose.yml up -d
□ 书城 mvn spring-boot:run -Dspring-boot.run.profiles=local
□ curl http://127.0.0.1:8080/actuator/health（若有）
□ curl http://127.0.0.1:8081/api/books/1
```

### Step M0.2 书城侧封装 LiteVodClient

在 `smart_bookstore` 新建包 `com.zx.media.client`（或 `com.zx.bookstore.media`）：

| 方法 | 对应 Lite VOD |
| --- | --- |
| `getMediaInfo(String fileId)` | `GET /vod/medias/{fileId}` |
| `getPlaySignature(String fileId, Integer exper)` | `GET /vod/signature/play?fileId=&exper=` |
| `deleteMedia(String fileId)` | `DELETE /vod/medias/{fileId}`（管理端用） |

使用 `RestTemplate` 或 `RestClient`，配置 `bookstore.media.lite-vod.base-url`。

### Step M0.3 配置类

```yaml
bookstore:
  media:
    lite-vod:
      enabled: true
      base-url: http://127.0.0.1:8080
```

`@ConditionalOnProperty` 便于本地未起 VOD 时不影响书城其他模块。

### Step M0.4 自测

```text
□ 已知 fileId，书城写单元测试或临时 Controller 能拉到 duration、coverUrl、status
□ VOD 未启动时，友好错误提示，不拖垮书城启动（enabled=false 可跳过）
```

## 五、M1：关联表 + 管理端绑定（第 2～3 天）

**目标**：书城知道「哪本书对应哪个视频 fileId」。

### Step M1.1 Flyway 建表（书城）

新建 `V2__book_media_ref.sql`（版本号按书城当前迁移顺延）：

```sql
CREATE TABLE book_media_ref (
  id                BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  book_id           BIGINT UNSIGNED NOT NULL COMMENT '关联 book.id',
  file_id           VARCHAR(64) NOT NULL COMMENT 'Lite VOD fileId',
  title             VARCHAR(128) NULL COMMENT '展示标题，默认取媒资名',
  media_type        VARCHAR(16) NOT NULL DEFAULT 'INTRO'
    COMMENT 'INTRO=导读 LECTURE=精讲 TRAILER=预告',
  preview_seconds   INT NOT NULL DEFAULT 300 COMMENT '未解锁时试看秒数，0=不允许试看',
  sort_order        INT NOT NULL DEFAULT 0,
  status            TINYINT NOT NULL DEFAULT 1 COMMENT '1=启用 0=下架',
  created_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_book_file (book_id, file_id),
  KEY idx_media_book (book_id),
  KEY idx_media_file (file_id),
  CONSTRAINT fk_media_book FOREIGN KEY (book_id) REFERENCES book(id)
) COMMENT='图书与 Lite VOD 媒资关联';
```

**说明**：

- 一本书可绑多个视频（导读 + 精讲），用 `sort_order` 排序  
- `file_id` 与 Lite VOD `media.file_id` 一致，**不同步视频二进制**  

### Step M1.2 书城四层代码

| 层级 | 示例 |
| --- | --- |
| Entity | `BookMediaRef.java` |
| Mapper / Repository | `BookMediaRefRepository` |
| Service | `BookMediaService`：绑定前调 VOD 校验 fileId 存在且 status=完成 |
| Admin Controller | `BookMediaAdminController` |

**管理端接口**：

```text
POST   /api/admin/books/{bookId}/media        ADMIN  绑定 { fileId, title?, mediaType?, previewSeconds? }
DELETE /api/admin/books/{bookId}/media/{id} ADMIN  解除绑定
GET    /api/admin/books/{bookId}/media        ADMIN  列表
PUT    /api/admin/books/{bookId}/media/{id}   ADMIN  改标题/试看秒数/排序
```

**绑定校验逻辑**：

1. `book` 存在且上架  
2. `LiteVodClient.getMediaInfo(fileId)` 返回且 `status=完成`  
3. 插入 `book_media_ref`  

### Step M1.3 用户端列表（不含 playUrl）

```text
GET /api/books/{bookId}/media    USER  返回 [{ id, title, mediaType, duration, coverUrl, previewSeconds }]
```

- `duration` / `coverUrl` 来自 VOD 查询（可 Redis 缓存 `media:info:{fileId}`，TTL 10 分钟）  
- **列表不下发 playUrl**，防止绕过鉴权  

### Step M1.4 自测

```text
□ ADMIN 绑定非法 fileId → 4xx
□ ADMIN 绑定成功 → GET 用户列表可见
□ 同一 book 绑两个 fileId → sort_order 正确
```

## 六、M2：用户端播放 + 试看（第 4～6 天）

**目标**：登录用户请求播放，未解锁时 Lite VOD 返回带 `exper` 的地址。

### Step M2.1 播放接口（书城）

```text
GET /api/books/{bookId}/media/{refId}/play    USER
Response: {
  "fileId": "...",
  "playUrl": "http://.../hls/.../index.m3u8?e=...&sign=...&exper=300",
  "preview": true,
  "previewSeconds": 300,
  "duration": 600
}
```

**Service 逻辑**：

```java
// 伪代码
BookMediaRef ref = loadRef(refId, bookId);
MediaInfo info = liteVodClient.getMediaInfo(ref.getFileId());
boolean fullAccess = accessService.canWatchFullMedia(userId, bookId);
Integer exper = fullAccess ? null : ref.getPreviewSeconds();
PlaySignature sig = liteVodClient.getPlaySignature(ref.getFileId(), exper);
return buildPlayResponse(sig, fullAccess, ref);
```

### Step M2.2 试看策略

| 策略 | 实现 | 推荐 |
| --- | --- | --- |
| L0 | 仅 `exper` 参数，依赖播放器停在前 N 秒 | MVP 够用 |
| L1 | Nginx 校验 `exper`，超时 403 | 中等 |
| L2 | Lite VOD 二期 `preview.m3u8` | 见 [试看 L2](../13-二期改动升级/03-试看L2.md) |

MVP 用 **L0 + 书城侧 preview 标记**；答辩说明 L2 为安全增强即可。

### Step M2.3 前端（可选，M5 可合并）

- 图书详情 Tab「配套视频」  
- 点击 → 调 `/play` → `hls.js` 挂载  
- `preview=true` 时 UI 提示「试看 N 分钟，借阅后可看全部」  

### Step M2.4 自测

```text
□ 未登录 → 401（若接口要求 USER）
□ 未借阅 → playUrl 带 exper=300，preview=true
□ 直接拿 playUrl 在浏览器可播试看段
□ exper 过期后 ts 请求失败（取决于 Nginx 配置）
```

| 内容类型 | 存储位置 | 原因 |
| --- | --- | --- |
| 视频原片 / HLS | MinIO | 体积大、需 CDN 分发、转码产物多文件 |
| 媒资元数据 | Lite VOD `media` 表 | fileId、duration、status |
| 书 ↔ 视频关系 | 书城 `book_media_ref` | 业务归属在书城 |
| 笔记 / 字幕文本 | 书城 MySQL 或 MinIO | 文本量可控，AI 友好 |

与「小说章节正文」类似：小规模可 MySQL，视频**几乎必用对象存储**（见 Lite VOD 架构）。
