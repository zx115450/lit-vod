# L3：切章写回

> **阶段**：L3 · **周期**：2～3 天  
> **目标**：Worker 按 `splitRule` 切章，每章一个 MinIO 对象 + 一条 `CHAPTER` media；提供 `GET /vod/medias/{sourceFileId}/chapters`。  
> **上一篇**：[L2 DOCUMENT 上传完成](./L2-DOCUMENT上传完成.md)　**下一篇**：[L4 对象签名与内部拉文本](./L4-对象签名与内部拉文本.md)

---

## 本步要做什么

媒资侧**正文真相源**在此步确立：切章结果写回 MinIO + `media` 表，书城只同步目录（对侧 B2）。

---

## 切章规则

| `splitRule` | 切分方式 |
| --- | --- |
| `MARKDOWN` | 行首 `^#{1,2}\s+` 作为章标题 |
| `TXT_CHAPTER` | 正则 `第[一二三四五六七八九十0-9]+章` |

| 项 | 约定 |
| --- | --- |
| 对象键 | `chap/{sourceFileId}/{nnn}.md`（三位序号，从 001） |
| 子 media | `asset_type=CHAPTER`，`parent_file_id=sourceFileId`，`chapter_no` 从 1 |
| 标题 | 匹配行去掉 `#` 后的文本 |
| 字数 | 章正文 UTF-8 字符数写入 `wordCount`（DTO 字段，可冗余在扩展列或查询时算） |

**失败语义**：切不出至少 1 章 → 父 `status=FAILED`，`error_msg` 可读，**不**插入空 CHAPTER 行。

---

## Worker 实现要点

新建 `DocumentSplitConsumer`（或 `SplitChapterHandler`），消费 `vod.document.split`：

```text
1. 从 MinIO 下载 DOCUMENT 原件（object_key）
2. 按 splitRule 解析章节列表
3. 对每个章节：
   a. 上传 chap/{sourceFileId}/{nnn}.md
   b. INSERT media（新 fileId=UUID，asset_type=CHAPTER，parent_file_id，chapter_no，filename）
4. 全部成功 → 父 DOCUMENT status=FINISHED
5. 任一步失败 → 父 FAILED；已写子章需回滚或标记 orphan（MVP：失败时 delete 已写 chap 前缀）
```

### 幂等与重跑

- 同一 DOCUMENT 重跑：建议先 `removePrefix(chap/{sourceFileId}/)`，再删 `parent_file_id=source` 的 CHAPTER 行，再重切
- MVP：**不支持「同 fileId 重切章」**，失败则管理员删 DOCUMENT 重传

### 与 FFmpeg 隔离

- 独立队列、并发 1
- 不调用 `FfmpegService`

---

## API：章目录

```text
GET /vod/medias/{sourceFileId}/chapters
```

响应：

```json
{
  "sourceFileId": "...",
  "chapters": [
    {
      "chapterNo": 1,
      "title": "持久化",
      "fileId": "chap-uuid-1",
      "wordCount": 1200,
      "assetType": "CHAPTER"
    }
  ]
}
```

| 父状态 | 行为 |
| --- | --- |
| PROCESSING | **200 + `chapters: []`**（补救查询 / 调试仍可用） |
| FINISHED | 200 + 按 `chapterNo` 排序的完整列表 |
| FAILED | 200 + `[]` 或 404；与总纲一致选 **200 + []** |

实现：`MediaMapper.findChaptersByParentFileId(sourceFileId)` + 排序。

---

## 状态机（DOCUMENT）

```text
UPLOADING → (commit) → PROCESSING → (split ok) → FINISHED
                              └→ (split fail) → FAILED
```

切章完成判定：**子 CHAPTER 条数 > 0 且父 status=FINISHED**（总纲 P1 验收）。

## 验证

样本：`lite-vod/samples/redis-preview.md`（≥3 个二级标题）。

```bash
1. 走 L2 上传 commit DOCUMENT + splitRule=MARKDOWN
2. 轮询 GET /vod/medias/{sourceFileId} 至 FINISHED（调试）；生产由 Worker Webhook 通知书城
3. GET /vod/medias/{sourceFileId}/chapters → length ≥ 3，chapterNo 递增
4. MinIO 控制台：chap/{sourceFileId}/001.md ...
5. 故意上传无标题 md → 父 FAILED，chapters 为空，无 CHAPTER 脏行
6. mp4 回归一条
```

把 `sourceFileId` 与各章 `fileId` 记入 [附录-联调样例](./附录-联调样例.md)。

## 完成标准

- [x] 3～5 章 Markdown 样本切出对应 CHAPTER 行
- [x] `GET .../chapters` 按 `chapterNo` 排序
- [x] MinIO 可见 `chap/` 前缀对象
- [x] 切章失败：父 FAILED，无空 CHAPTER 子行
- [x] 视频 PROCEDURE 不受 DOCUMENT 队列阻塞

> 实现落点：`ChapterSplitter`（MARKDOWN / TXT_CHAPTER）；Worker `DocumentSplitConsumer` 写
> `chap/{source}/{nnn}.md` + CHAPTER media；`GET /vod/medias/{sourceFileId}/chapters`；
> 失败回滚 `removePrefix` + `deleteByParentFileId`。样本：`samples/redis-preview.md`。
> CHAPTER 的 `page_count` MVP 复用为 `wordCount`。
