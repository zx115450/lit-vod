# 04：踩坑速查

## 问题：构建任务卡在 `apk add openjdk17-jdk maven`

### 现象
`build_push` 任务启动几分钟后，日志停在 `(7/28) Installing openjdk17-jre-headless`。

### 原因
`docker:24` 镜像里没有 JDK/Maven，临时通过 Alpine 官方源安装，国内极慢。

### 解决
把 `build_push` 的 `image` 从 `docker:24` 改为 `maven:3.9-eclipse-temurin-17`，只额外下载一个静态 Docker CLI 二进制。

---

## 问题：`docker login` 报 `invalid control character in URL`

### 现象
```text
Error response from daemon: unable to parse server address:
parse "https://\t\n192.168.150.104:8089": net/url: invalid control character in URL
```

### 原因
GitLab CI/CD 变量 `HARBOR_HOST` 的值前后带了 `\t\n`。

### 解决
重新编辑变量，去掉首尾空白，或使用脚本读取时 `echo -n`、`sed 's/^[[:space:]]*//;s/[[:space:]]*$//'`。

## 问题：Maven 依赖从 Maven Central 下载只有几 kB/s

### 现象
日志反复出现 `Downloading from central`，速度 2–3 kB/s。

### 原因
`maven:3.9-eclipse-temurin-17` 默认使用国外 Maven Central。

### 解决
在 `.gitlab-ci.yml` 的 `before_script` 中写入 `~/.m2/settings.xml`，把 central 镜像到阿里云：

```xml
<mirror>
  <id>aliyun-central</id>
  <mirrorOf>central</mirrorOf>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

## 问题：`docker:24` 镜像实际上是 dind

### 现象
执行 `docker info` 或 `docker build` 报错，或者容器启动命令是 `dockerd-entrypoint.sh`。

### 原因
某些镜像源把 `docker:24` 和 `docker:24-dind` 打成同一个镜像。

### 解决
客户端用 `docker:24-cli` 标签，dind 服务用 `docker:24-dind`。或者直接用 Maven 镜像 + 下载 Docker CLI 二进制。

---

## 问题：Harbor 部署时默认端口 80 被占用

### 现象
宿主机已有 `vod-nginx` 监听 80，Harbor 启动冲突。

### 解决
`harbor.yml` 中 `http.port: 8089`，`.gitlab-ci.yml` 和 Docker daemon 都使用 `192.168.150.104:8089`。

---

## 问题：首次流水线成功后缓存没生效

### 现象
任务失败后重试，Maven 依赖仍然重新下载。

### 原因
GitLab cache 只在任务成功结束时上传。失败那次不会留下 cache。

### 解决
让 `test` 先成功跑通一次，成功后 `.m2/repository` 会进入 cache，后续 `build_push` 也能复用。
