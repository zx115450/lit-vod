# 04：踩坑速查

## 问题：构建任务卡在 `apk add openjdk17-jdk maven`

### 现象
`build_push` 任务启动几分钟后，日志停在 `(7/28) Installing openjdk17-jre-headless`。

### 原因
`docker:24` 镜像里没有 JDK/Maven，临时通过 Alpine 官方源安装，国内极慢。

### 解决
把 `build_push` 的 `image` 从 `docker:24` 改为 `maven:3.9-eclipse-temurin-17`，只额外下载一个静态 Docker CLI 二进制。

## 问题：`docker login` 报 `invalid control character in URL`

### 现象
```text
Error response from daemon: unable to parse server address:
parse "https://\t\n192.168.150.104:8089": net/url: invalid control character in URL
```

### 原因
GitLab CI/CD 变量 `HARBOR_HOST` 的值前后带了 `\t\n`。

### 解决
重新编辑变量，去掉首尾空白，或使用脚本读取时 `echo -n`、`sed 's/^[[:space:]]*//;s/[[:space:]]*$//'`。

## 问题：Maven 依赖从 Maven Central 下载只有几 kB/s

### 现象
日志反复出现 `Downloading from central`，速度 2–3 kB/s。

### 原因
`maven:3.9-eclipse-temurin-17` 默认使用国外 Maven Central。

### 解决
在 `.gitlab-ci.yml` 的 `before_script` 中写入 `~/.m2/settings.xml`，把 central 镜像到阿里云：

```xml
<mirror>
  <id>aliyun-central</id>
  <mirrorOf>central</mirrorOf>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

## 问题：`docker:24` 镜像实际上是 dind

### 现象
执行 `docker info` 或 `docker build` 报错，或者容器启动命令是 `dockerd-entrypoint.sh`。

### 原因
某些镜像源把 `docker:24` 和 `docker:24-dind` 打成同一个镜像。

### 解决
客户端用 `docker:24-cli` 标签，dind 服务用 `docker:24-dind`。或者直接用 Maven 镜像 + 下载 Docker CLI 二进制。

## 问题：Harbor 部署时默认端口 80 被占用

### 现象
宿主机已有 `vod-nginx` 监听 80，Harbor 启动冲突。

### 解决
`harbor.yml` 中 `http.port: 8089`，`.gitlab-ci.yml` 和 Docker daemon 都使用 `192.168.150.104:8089`。

## 问题：首次流水线成功后缓存没生效

### 现象
任务失败后重试，Maven 依赖仍然重新下载。

### 原因
GitLab cache 只在任务成功结束时上传。失败那次不会留下 cache。

### 解决
让 `test` 先成功跑通一次，成功后 `.m2/repository` 会进入 cache，后续 `build_push` 也能复用。

## 问题：分片上传返回 501，环境变量已经是 true

### 现象
演示页点「分片上传」，`POST /vod/signature/upload/multipart` 返回 `501 Not Implemented`。容器里 `VOD_UPLOAD_MULTIPART_ENABLED=true`，镜像内 `application.yml` 的默认值也是 `true`，接口仍然报 multipart 未开启。

### 原因
`UploadProperties` 同时有规范构造方法和一个无参构造。无参构造把 `multipartEnabled` 写死为 `false`。

Spring Boot 3.2 在配置类有多个构造方法、又没有标明用哪一个时，会走无参构造创建对象，不再按 `vod.upload.*` 做构造绑定。因此下面两处都不生效：

- 环境变量 `VOD_UPLOAD_MULTIPART_ENABLED`
- `application.yml` 里的 `vod.upload.multipart-enabled`

服务里 `if (!uploadProps.multipartEnabled())` 一直为真，于是固定抛 501。这和接口没实现不是一回事，路由已经进来了。

### 解决
删掉无参构造，只保留一个带 `@DefaultValue` 的构造方法，让 Spring 绑定配置。改完后同一请求应返回 200，而不再是 501。

注意：只改运行中的环境变量不够，必须换成包含这次构造方法修改的 `vod-api` 镜像。

## 问题：分片改造后 `mvn test` 编译失败

### 现象
推送分片上传后，GitLab 流水线停在 `test`。`build_push` 因 `needs: ["test"]` 不会执行。

### 原因
`MinioStorage` 增加了 `MinioAsyncClient` 参数，构造方法变为 4 个参数。`MinioStorageIT` 仍调用旧的 3 参数构造：

```text
required: MinioClient, MinioClient, MinioAsyncClient, MinioProperties
found:    MinioClient, MinioClient, MinioProperties
```

该类在 `src/test/java`。MinIO 没启动时用例会被跳过，但测试代码必须先编译通过，`mvn test` 仍会失败。

### 解决
在 `MinioStorageIT` 中再构建一个 `MinioAsyncClient`，按新构造方法传入。

## 问题：转码任务一直 PROCESSING / PENDING，Worker 起不来

### 现象
- `media.status = 2`（PROCESSING），`media_task.status = 0`（PENDING），`attempt = 0`，`finished_at` 为空
- RabbitMQ 队列 `vod.procedure`：`messages_ready ≥ 1`，但 **`consumers = 0`**
- 容器：`lite-vod-vod-api-1` Up，`lite-vod-vod-worker-1` 为 `Exited (1)`；宿主机无 8081 监听

### 原因
`vod-worker` 的 `application.yml` 写了两个顶层 `vod:`（一块 `abr`，一块 `callback`）。SnakeYAML 不允许重复 key，启动直接失败：

```text
org.yaml.snakeyaml.constructor.DuplicateKeyException: found duplicate key vod
```

API 仍可投递消息，队列有积压，但没有消费者，任务永远不会变 RUNNING。

### 解决
合并为一个顶层 `vod:`，把 `abr` 与 `callback` 作为其子键。改完后需重建并部署 `vod-worker` 镜像；队列里未 ack 的消息会在 Worker 起来后被消费。

排查时可先看：`docker logs lite-vod-vod-worker-1`、RabbitMQ Management（15672）的 `vod.procedure` 消费者数。
