# 05：部署过程总结

> 目标：说明代码推到 `main` 之后，镜像如何进 Harbor，以及如何手动部署到 `192.168.150.104`。

## 整条链路

推到 `main` 后，测试和构建自动跑。部署不会自动开始，要在 GitLab 里手动点 `deploy_staging`。

```text
git push main
  → test（Maven 单测）
  → build_push（打包并推送 vod-api、vod-worker 到 Harbor）
  → deploy_staging（手动：SSH 到目标机，compose pull && up，再查健康检查）
```

镜像标签是这次提交的短哈希，变量名是 `IMAGE_TAG`。

## 各机器上是什么

| 角色 | 地址 | 作用 |
| --- | --- | --- |
| GitLab | `http://192.168.150.104:8088` | 存代码，跑流水线 |
| Harbor | `192.168.150.104:8089` | 存 `vod-api`、`vod-worker` 镜像，项目名 `lite-vod` |
| Runner | 同一台机器上的 `docker-runner-104` | 执行 CI Job |
| 部署目录 | `/opt/lite-vod` | Compose 和 `.env` 所在位置 |

这次演示机就是 `192.168.150.104` 自己。MySQL、RabbitMQ、MinIO、Nginx 已经在这台机器上跑着，部署不会再启动一套。

## 自动完成的部分

1. `test`：镜像 `maven:3.9-eclipse-temurin-17`，Maven 走阿里云。
2. `build_push`：镜像 `192.168.150.104:8089/lite-vod/ci-maven:3.9-17`（已含 Maven、JDK 17 和 docker 命令）。构建 `vod-api`、`vod-worker` 后推到 Harbor。
   - `vod-api` 基础镜像：`192.168.150.104:8089/lite-vod/temurin:17-jre-jammy`
   - `vod-worker` 基础镜像：`192.168.150.104:8089/lite-vod/worker-base:ffmpeg`

## 手动部署时发生的事

GitLab 变量（项目 → Settings → CI/CD → Variables）：

| 变量 | 本次取值 | 说明 |
| --- | --- | --- |
| `DEPLOY_HOST` | `192.168.150.104` | SSH 地址 |
| `DEPLOY_USER` | `root` | SSH 用户 |
| `DEPLOY_SSH_KEY` | File 类型 | 私钥文件，不是密码，也不是屏幕上的指纹图案 |
| `DEPLOY_PATH` | `/opt/lite-vod` | Compose 目录 |

对应公钥在目标机 `/root/.ssh/authorized_keys`。

点 `deploy_staging` 之后，Runner 做这些事：

1. 用 Alpine 镜像，软件源改成阿里云，安装 `openssh-client` 和 `curl`。
2. 从 `DEPLOY_SSH_KEY` 这个文件读出私钥，SSH 到目标机。
3. 进入 `/opt/lite-vod`，把 `.env` 里的 `IMAGE_TAG` 写成这次提交的短哈希。
4. `docker login` Harbor，然后：

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml pull vod-api vod-worker
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d vod-api vod-worker
```

5. 最多约 36 秒，反复请求 `http://127.0.0.1:8080/vod/health`。返回 `{"status":"ok"}` 才算成功。

两个 Compose 文件分工：

- `docker-compose.yml`：本机已有的 MySQL、RabbitMQ、MinIO、Nginx。流水线不会改它们。
- `docker-compose.prod.yml`：只覆盖 `vod-api`、`vod-worker`。从 Harbor 拉镜像，数据库和对象存储仍指向 `192.168.150.104`。`vod-api` 映射 `8080`。

流水线不会把这两个 YAML 拷到目标机。目录里必须事先放好。改了仓库里的 Compose 后，要自己再拷一次。

## 这次已经确认的结果

- 镜像标签 `6e068f9e` 已从 Harbor 拉到本机。
- 容器 `lite-vod-vod-api-1`、`lite-vod-vod-worker-1` 已启动。
- `http://127.0.0.1:8080/vod/health` 返回 `{"status":"ok"}`。

## 踩过的坑

1. **`DEPLOY_SSH_KEY` 必须是完整私钥。** 屏幕上的随机图案不是钥匙。普通变量会吃掉换行，SSH 报 `error in libcrypto`。类型要用 File，脚本用文件路径读取，不能 `echo` 变量值。
2. **目标机上要先有 `docker-compose.prod.yml`。** 没有这个文件时，compose 直接报 `no such file or directory`。
3. **不要在这台机器上再启动一套 MySQL。** `3306`、`5672`、`9000`、`80` 已被占用。应用容器连现有实例。
4. **健康检查不能只等 5 秒。** Spring Boot 大约 11 秒才监听 `8080`。提前请求时 Docker 会重置连接，`curl` 退出码 `56`。
5. **部署 Job 里的 `apk` 走阿里云。** Alpine 官方源不稳定时，会卡在安装 `openssh-client`。
