# 点播与对象存储：前置知识

> 面向没有做过视频存储 / 点播项目的读者。  
> 读完应能看懂：[Lite VOD 实现文档](./04-轻量版云点播-Lite-VOD-实现文档.md) 和 [分步实现指南](./05-分步实现指南/00-阅读说明.md)。  
> 不要求先会 FFmpeg 命令或 MinIO 运维；概念对齐即可动手。

---

## 一、先建立场景

天机学堂这类产品要解决的不是「把 mp4 丢进磁盘」，而是：

1. 老师把课上传上去（文件可能几百 MB～几 GB）
2. 系统处理后，学员在浏览器里流畅播放
3. 没登录、过期、没买课的人不能随便拖走整部课
4. 业务库里能查到：这个视频处理好没有、时长多少、封面是哪张

云厂商把这套能力打包成 **云点播（VOD，Video on Demand）**，例如腾讯云 VOD。Lite VOD 是用开源组件自建一个「常用子集」。

**点播** 和 **直播** 不同：点播是「已经录好、随时按进度看」；直播是「正在发生、不能随便拖到未来」。本项目只做点播。

---

## 二、为什么不能「Java 接口直接收文件再存磁盘」

入门项目常写：`POST /upload`，Multipart 传到应用服务器，再 `Files.copy` 到某目录，用 `http://服务器/files/xxx.mp4` 播放。

课视频会很快撑不住：

| 问题 | 说明 |
| --- | --- |
| 带宽打满业务机 | 所有字节都经 Spring，上传和播放抢 CPU / 网卡 |
| 水平扩展难 | 文件在 A 机器磁盘上，请求打到 B 就 404 |
| 原片不适合网页播 | 编码、码率、拖进度、弱网体验都差 |
| 权限难做 | 静态目录一公开，链接就能被转发盗播 |

所以工业界拆成三层：

- **对象存储**：只存字节（原片、切片、封面）
- **元数据库**：存「这是哪个视频、状态如何」（MySQL）
- **业务 API**：发凭证、改状态、投递任务，**不经手文件流**

这是后面所有设计的出发点。

## 三、对象存储（Object Storage）

### 3.1 它是什么

把数据看成一个个 **对象（Object）**：一份数据 + 一个名字 + 少量元数据（大小、类型）。

名字一般叫 **对象键（object key）**，长得像路径，其实只是字符串，例如：

```text
raw/f7c2a1b0e9d84f6a/source.mp4
```

对象放在 **桶（Bucket）** 里。Lite VOD 用一个桶，名字叫 `vod`。

常见云产品：AWS S3、阿里云 OSS、腾讯云 COS。它们的 API 很像，常统称 **S3 兼容**。

**MinIO** 是开源的 S3 兼容存储，可以在 Docker 里跑，本地开发和私有化都能用。对应用来说：学会 MinIO，以后换 COS/OSS 主要是改 endpoint 和密钥。

### 3.2 和「网盘文件夹」的差别

- 没有真正的多层文件夹，`raw/xxx/source.mp4` 只是 key 里的斜杠
- 读写按对象整体进行（大文件另有分片上传）
- 默认 **不该匿名公开读**；谁能读由策略或「带签名的临时 URL」决定

### 3.3 预签名 URL（Presigned URL）

应用服务器用 MinIO 的密钥，算出一个 **短时有效的 HTTP 地址**。浏览器拿这个地址 **直接 PUT 到 MinIO**，不必把文件先交给 Java。

这就是「申请上传凭证 → 客户端直传」：

```text
前端  →  vod-api：我要上传（只拿 URL，几 KB 的 JSON）
前端  →  MinIO：PUT 几百 MB 的 mp4
前端  →  vod-api：我传完了，请登记（JSON，仍无文件流）
```

密钥留在服务器，不会发给浏览器。URL 过期后就不能再传。

## 四、视频文件里到底有什么

日常说的「一个 mp4」其实叠了多层概念，转码时会碰到：

| 名词 | 含义 | 例子 |
| --- | --- | --- |
| 容器（Container） | 包装格式，像盒子 | MP4、MPEG-TS |
| 编码（Codec） | 画面/声音怎么压缩 | 视频 H.264；音频 AAC |
| 分辨率 | 画面像素 | 1920×1080、1280×720 |
| 码率 | 每秒多少数据 | 越高越清晰、文件越大 |
| 时长 | 能播多久 | 写入库字段 `duration` |

老师导出的 mp4 可能是 4K、奇怪编码、或码率极高。浏览器和手机不一定吃得消，也不适合直接当点播地址。

**FFmpeg** 是业界常用的命令行工具：读入一种组合，输出另一种组合（换编码、改分辨率、切片）。Lite VOD 的 Worker 容器里会安装它。**ffprobe** 是它的「只看不转」同伴，用来读时长等信息。

你暂时不需要成为音视频工程师，只要记住：

- 上传的叫 **原片（raw / source）**
- 给学员播的是 **转码产物**（本项目里是 HLS）

---

## 五、转码是在干什么

**转码（Transcode）**：把原片改写成「适合在网上点播」的格式和规格。内容还是那一课，文件形态变了。

Lite VOD 首期 Worker 做两件事：

1. 压到约 720p、H.264 + AAC，并切成 HLS
2. 截一张封面图（例如第 3 秒）

然后把结果上传回 MinIO，库里把状态改成「处理完成」。在此之前不应给学员签发正式播放地址。

转码 **非常吃 CPU**，所以不要放在处理 HTTP 的同一进程里拼命同步跑。正确做法是：API 只投递任务，**独立 Worker** 慢慢转。队列积压就加 Worker 副本。

---

## 六、HLS：网页点播的常用协议

**HLS（HTTP Live Streaming）** 用普通 HTTP 播视频。点播时典型结构：

```text
index.m3u8          ← 文本清单：有哪些片段、顺序、每段几秒
segment_000.ts
segment_001.ts
...
```

播放器（网页里常用 **hls.js**）先拉 m3u8，再按需拉 ts。于是：

- 可以边下边播
- 拖进度 = 换一批切片
- 和 Nginx、CDN 是同一套 HTTP，好缓存

首期只有 **一档 720p**。二期才可能出现 `master.m3u8` 下面挂 360p/720p/1080p 多套切片（自适应码率）。

**不是**把原 mp4 改个后缀叫 HLS；必须经过 FFmpeg 切片生成上述文件。

## 七、媒资、fileId、状态机

**媒资** 就是「一条视频资产」在系统里的记录。

对外常用一个稳定 ID，腾讯云叫 `fileId`。Lite VOD 自己生成 UUID 风格的 `file_id`，前后端、播放 URL、对象路径都用它对齐：

```text
raw/{fileId}/source.mp4
hls/{fileId}/index.m3u8
cover/{fileId}.jpg
```

MySQL 存状态，不存视频二进制。常见状态：

```text
UPLOADING   已发上传凭证，文件可能还在传
UPLOADED    桶里已有原片
PROCESSING  正在转码
PROCESSED   可播放
FAILED      转码失败，可读 error_msg
```

列表页「处理完成」对应 `PROCESSED`。

---

## 八、异步任务与消息队列

「确认上传」如果同步等 FFmpeg 结束，HTTP 会超时，接口也会被转码拖死。

标准模式：

1. API 写任务表，往 **RabbitMQ** 丢一条消息 `{fileId, objectKey}`
2. 立刻返回「处理中」
3. **vod-worker** 收到消息再下载、转码、回传、更新库
4. 可选：Webhook / 拉取事件，通知业务「封面和时长好了」

消息队列保证：API 与 Worker 解耦；Worker 挂了消息还在，重启能继续；需要时多开几个消费者。

天机学堂对接腾讯时，云侧转码结束会有 Procedure 事件；自建时用任务表 + MQ 模拟同一件事情。

## 九、播放为什么还要「签名」

桶若对全世界可读，知道 URL 就能白嫖流量和内容。

正确做法：

1. 业务确认「这个人可以看」（课表、试看等，由 `tj-media` 做）
2. `vod-api` 签发 **短时播放 URL**，带过期时间 `e` 和 `sign`
3. 浏览器把 URL 给 hls.js
4. **Nginx** 校验签名合法、未过期，再 **反代** 到 MinIO 取切片

签名常用 **HMAC**：用只有服务器知道的 `VOD_PLAY_SECRET`，对「路径 + 过期时间」做哈希。改 path、改 fileId、改过期时间，哈希对不上，网关返回 403。

这和「登录 Cookie」不是同一层：播放器拉的是成百上千个 ts，每个请求都要能验，用带签名的 URL 最省事。

**试看（exper）**：只允许看前 N 秒。真正防拖进度要靠「只产出预览切片」等手段；首期可能只做短时 Token 或网关超时，安全性较低。实现文档里有分级说明。

## 十、Nginx 在这里扮演什么

MinIO 自己有地址（如 9000 端口），但不要让学员浏览器当网盘来用。

Nginx（或网关）负责：

- 统一播放域名，例如 `http://localhost/hls/...`
- 验签
- 把合法请求转发给 MinIO（**反向代理**）
- 需要时加 CORS、缓存头

开发阶段也可以用 Spring Filter 代替验签，道理相同：应用校验通过后，才去存储读对象。

## 十一、一条请求在系统里怎么走

上传（管理端）：

```text
申请凭证 → 直传 MinIO → 确认上传 → 入库并投递 MQ → Worker 转码 → 状态 PROCESSED
```

播放（学员端）：

```text
业务鉴权（天机）→ 向 VOD 申请播放签名 → hls.js 拉 m3u8/ts
→ Nginx 验签 → MinIO 返回切片
```

记住两句话：

- **字节走存储，状态走数据库，任务走队列**
- **VOD 负责能播；业务负责该不该播**

## 十二、和「普通后端」对应的一张表

| 你已经熟悉的 | 点播里的对应物 |
| --- | --- |
| MySQL 存订单 | MySQL 存媒资元数据 |
| 本地 `uploads/` 目录 | MinIO 对象 |
| 同步在 Controller 里处理 | MQ + Worker 异步转码 |
| JWT 登录接口 | 播放签名 URL（给播放器，不是给人看后台） |
| 静态资源 Nginx | 验签后反代切片 |
| 调用第三方支付 SDK | 调用腾讯 VOD 或 Lite VOD HTTP API |

## 十三、名词速查

| 词 | 一句话 |
| --- | --- |
| VOD | 视频点播服务 |
| 媒资 | 一条视频在系统中的档案 |
| fileId | 对外唯一视频 ID |
| Bucket / Object / Key | 桶 / 对象 / 对象名 |
| 预签名 URL | 临时授权的直传或下载地址 |
| 直传 | 浏览器直接传存储，不经业务机 |
| 转码 | 改编码/分辨率/切片，便于播放 |
| HLS / m3u8 / ts | 清单 + 小片段的点播方式 |
| FFmpeg | 转码用的命令行工具 |
| Procedure | 腾讯云「转码+封面」一类任务流 |
| HMAC 播放签名 | 用密钥给播放 URL 盖章防盗链 |
| 反代 | 网关替浏览器去回源拉文件 |
| Worker | 专门干活的后台进程，不对外提供页面 |

## 十五、动手前不必先精通的

下面这些可以边做边查，不要卡在预习上：

- FFmpeg 每一个参数的声学/视觉含义
- HLS 规范全文、DRM、广电审核
- MinIO 集群纠删码、生产级 CDN
- 自适应码率算法

首期成功标准只有：直传 → 处理完成 → 带签名能播 → 过期/篡改不能播 → Compose 能拉起。
