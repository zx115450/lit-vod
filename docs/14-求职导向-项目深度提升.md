> 面向 Lite VOD **主路径已可演示**、希望简历与面试再上一个台阶的同学。

## 1. 先定边界

当前项目已经够「写进简历」：上传 → 转码 → 签名播放闭环清楚。继续堆直播、DRM、自研编码器，对多数 Java 后端岗性价比低，且仓库里已有远期思路，不必重复立项。

加深时坚持三条：

1. **一项能力一个分支 / 一 PR**，可演示、可回滚  
2. **优先补「工程可信度」**：安全、可靠性、可观测、生产网关——比再加一个业务功能更像「上过线」  
3. **简历只写亲手跑通的**；文档方案未落地的，面试只能当「了解」，不能当「做过」

与现有文档的关系：

建议选法：

- **时间紧（1～2 周）**：A + B，或 A + C（二选一网关 / MQ，再加可观测）

## 3. 方向详解

### A. 可观测落地（P0）

**现状**：健康检查有；转码失败靠表字段与日志；[05-可观测](./13-二期改动升级/05-可观测与运维增强.md) 多为方案。

**做什么（最小可演示）**：

1. `vod-api` / `vod-worker` 引入 Actuator + Micrometer，暴露 `/actuator/prometheus`（演示环境加简单鉴权或仅内网）  
2. 结构化日志字段固定：`fileId`、`taskId`、`status`、`costMs`、`attempt`  
3. 业务计数：上传凭证发放、commit 4xx、转码成功/失败、验签 403、回调失败  
4. 可选：定时 SQL 扫 `PENDING` / `PROCESSING` 过久任务，打 WARN

**验收**：

- [ ] 能回答「最近一小时转码平均耗时、失败次数」  
- [ ] 能发现卡住超过 N 分钟的任务  
- [ ] 指标端点不对公网裸奔

**面试怎么讲**：从「能跑」到「能看见」；指标如何支撑扩容 Worker、发现毒文件。

**不要做**：一上来上完整 ELK + SkyWalking；演示环境过重。

---

### B. 播放网关生产化：Nginx `auth_request`（P0）

**现状（已落地）**：Compose 默认 Nginx `auth_request` → `/internal/play-auth`；`.m3u8` 由 Java 改写，`.ts` 直反 MinIO。本地可用 `VOD_PLAY_GATEWAY_FILTER_ENABLED=true` 切回 Filter。详见 [08-Nginx auth_request 播放网关](./06-工程化实践记录/08-Nginx-auth_request播放网关.md)。

**做什么**（对照仓库即可复述）：

1. Nginx：`/hls/` 走 `auth_request` 调 `vod-api` 轻量验签接口（只验签，不吐片）  
2. 验签通过后，`.ts` 直反 MinIO；`.m3u8` 仍走 Java 补签名 query  
3. 保留 Filter 作为本地无 Nginx 时的开发开关  
4. Compose：`VOD_PLAY_PUBLIC_BASE=http://localhost`，`VOD_PLAY_GATEWAY_FILTER_ENABLED=false`

**验收**：

- [x] 错误签名 / 过期 → 403；学员入口为 Nginx `:80`（勿把 MinIO `:9000` 当播放地址）  
- [x] 合法请求下，大 TS 流量主要走 Nginx→存储，不经 Spring 堆内存  
- [ ] 本机 Compose 起齐后演示页 / curl 联调勾选（Docker 未开时待补）

**面试怎么讲**：鉴权与静态分发解耦；为何云厂商也是「签名 URL / 边缘鉴权 + CDN 源站」，本项目用 Nginx 对齐同一思想。

**不要做**：自研完整商业 CDN 调度（见远期 DRM/CDN 文档）。

---

### C. MQ 与消费可靠性（P0）

**现状**：RabbitMQ 投递 + Worker 消费；有 `attempt` 与失败落库味道，但死信、并发、幂等往往是面试追问盲区。

**做什么**：

1. 业务队列 + **死信队列（DLQ）**：重试耗尽进 DLQ，可人工 / 工具重放  
2. 消费幂等：同一 `taskId` 成功态不重复转码；重复投递可安全 ack  
3. 明确重试策略：可重试（临时 IO）vs 不可重试（坏文件、参数错）  
4. 可选：消费端 prefetch / 并发上限，避免一台机器同时转爆盘

**验收**：

- [ ] 故意投递毒消息，最终进 DLQ，且不拖死主队列  
- [ ] 重复投递同一任务，媒资仍只有一份成功产物  
- [ ] 文档写清：消息丢了如何用 `media_task` 对账补偿

**面试怎么讲**：至少一次投递下的幂等；毒消息隔离；任务表才是真相源。

---

### D. 管理 API 鉴权（P0）

**现状**：播放有 HMAC；媒资列表 / 删除 / 上传凭证等管理面基本开放（Demo 可接受，简历易被追问）。

**做什么**：

1. Spring Security（或等价 Filter）：管理接口要 Token / Basic（演示可用固定 Admin JWT）  
2. 播放签发可分：业务服务持密钥调用 vs 浏览器不可直接打管理 API  
3. 明确边界：用户课权仍在业务侧（见 [课表鉴权边界](./13-二期改动升级/远期能力实现思路/04-课表鉴权与业务边界.md)），Lite VOD 只做「谁能调管理面」

**验收**：

- [ ] 无 Token 访问删除 / 列表 → 401  
- [ ] 播放链路（已签名 URL）不受影响  
- [ ] 密钥与 Admin 口令仅环境变量

**面试怎么讲**：播放防盗链 ≠ 管理面鉴权；最小权限与密钥分层。

---

### E. Worker 容量与优雅停机（P1）

**现状**：`CommandRunner` 已有超时、有界输出等工程点，适合再往「资源治理」延伸。

**做什么**：

1. 配置最大并行转码数（信号量 / 线程池）  
2. 磁盘水位或临时目录清理策略（转码临时文件必删）  
3. 收到 SIGTERM：停止拉取新消息，等待当前任务结束或超时强制结束并回写可重试状态  
4. 与方向 A 联动：并行度、队列堆积可观测

**验收**：

- [ ] 压多个任务时并行数不超过配置  
- [ ] `docker stop` / compose stop 时不丢「正在跑却已 ack」的黑锅（或明确策略并写进文档）  
- [ ] 临时目录不无限膨胀

**面试怎么讲**：CPU 密集任务的背压；优雅停机与至少一次消费的组合。

---

### F. 端到端自动化验收（P1）

**现状**：单测较全；端到端多靠手工 Compose。

**做什么（选一条主路径即可）**：

1. Testcontainers：MySQL + RabbitMQ + MinIO，跑「假转码或短视频」冒烟  
2. 或 CI job：`docker compose` 起来后 curl 健康检查 + 固定小文件上传 commit（转码可 mock Worker）  
3. 把冒烟挂进 GitLab CI，失败阻断 deploy

**验收**：

- [ ] MR / main 流水线能自动跑通最小闭环或明确的 mock 闭环  
- [ ] README / 步骤文档写清如何本地跑同一套

**面试怎么讲**：质量门禁；测试金字塔里 IT 补的是契约与装配，不是替代单测。

---

### G. 媒资生命周期清理（P1）

**现状**：有删除接口；直传未 commit、失败残留、Abort 后的分片，长期会脏。

**做什么**：

1. 定时任务：`UPLOADING` 超过 TTL → 删库记录 + 尝试删对象  
2. Multipart：Abort / 过期 uploadId 清理（若二期分片已上）  
3. 失败任务可选保留对象 N 天便于排障，再删  
4. 对账脚本：DB 有、MinIO 无 / 反之，出报告

**验收**：

- [ ] 制造未 commit 上传，TTL 后对象与记录可清理  
- [ ] 清理逻辑幂等、可干跑（dry-run）

**面试怎么讲**：对象存储成本与一致性；「直传成功但业务未确认」的生命周期。

---

### H. 播放限流与签名吊销（P2）

**适用**：想体现 Redis、防刷；非必须。

**做什么**：

1. 按 `fileId` + IP / Token 的简易限流（网关或 API）  
2. 可选：Redis 吊销集合，验签额外查「是否作废」（妥协：短 TTL 签名可先不吊销）  
3. 与试看、403 指标联动

**验收**：超限返回 429；吊销后未过期签名也 403。

**面试怎么讲**：签名过期是主手段，吊销是补充；分布式限流的位置（网关 vs 应用）。

---

### I. 压测与容量估算（P2）

**做什么**：不必上复杂平台。

1. 用固定 1080p 样片测：单 Worker 平均转码耗时、磁盘峰值  
2. 估算：日上传量 → 需要的并行 Worker 数  
3. 播放侧：签名 QPS（轻）vs TS 带宽（重）分离估算  
4. 输出一页「容量假设与瓶颈」Markdown，面试可投屏

**验收**：有可复现命令 + 一张表（输入假设 → 输出并行度）。

## 4. 不建议为求职单独加深的方向

| 方向 | 原因 |
| --- | --- |
| 直播 / RTC | 另一条产品线；见远期文档即可口述 |
| 商业 DRM | 证书与法务重，Demo 难闭环 |
| 自研编码器 | 与 Java 岗匹配度低 |
| 把课权做进 VOD | 架构上反模式，面试易被打 |
| 再堆演示页 UI | 对后端深度帮助小 |

二期若尚未收尾：**先完成 Multipart / ABR / L2 中你简历要写的那几项**，再开本文 P0。半截功能写进简历风险高于少写一项。

```text

```

### 路径 3：已有二期功能、缺「像上线」

```text
只做 A + B + C，每项写一页工程化实践记录（可挂 docs/06）
```

每做完一项，同步更新：

1. 简历项目子弹（只写已验收项）
