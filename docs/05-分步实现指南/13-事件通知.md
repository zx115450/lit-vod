# 步骤 13：事件通知

> 分期：Phase 2 可选。  
> 目标：转码结束后通知业务：Webhook 或模拟腾讯 PullEvents。  
> 上一篇：[演示页播放验证](./12-演示页播放验证.md)　下一篇：[删除媒资](./14-删除媒资.md)

## 本步要做什么

天机学堂用 `PullEventTask` 拉云事件再 `updateMediaProcedureResult`。Lite VOD 提供等价物，便于以后替换 `TencentMediaStorage`。

首期 **二选一即可**，优先 Webhook（实现更短）。

## 方案 A：Webhook（推荐）

Worker 在 `PROCESSED` / `FAILED` 之后 HTTP POST 配置的 `VOD_CALLBACK_URL`。

Body 示例：

```json
{
  "fileId": "f7c2a1b0e9d84f6a",
  "status": "PROCESSED",
  "coverUrl": "cover/f7c2a1b0e9d84f6a.jpg",
  "duration": 123.4,
  "errorMsg": null
}
```

要求：

- 超时短、失败重试 2～3 次
- 不要阻塞删除临时目录（回调可异步）
- 回调失败不影响媒资已成功的状态（只打日志或入死信）

## 方案 B：PullEvents

- `GET /vod/events/pull`：返回已完成未确认事件
- `POST /vod/events/confirm`：body 为 eventId 列表

需增表 `media_event`（id、file_id、payload、acked）。Worker 写事件，业务轮询。对齐腾讯拉模式。

## 操作步骤

1. 选定 A 或 B（演示选 A）
2. 配置回调 URL；本地可用 [webhook.site](https://webhook.site) 或 `vod-api` 内一个测试 Controller
3. 跑一次成功转码，确认收到 JSON
4. 跑一次失败转码，确认 `status=FAILED`

## 完成标准

- [ ] 成功 / 失败至少一种通道能被业务感知
- [ ] 事件不重复导致业务重复写花（业务侧按 fileId 幂等；VOD 侧尽量 at-least-once）

## 本步不做

- 不改天机 `PullEventTask`（放到第 16 步）
