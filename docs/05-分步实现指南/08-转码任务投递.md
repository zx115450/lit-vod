# 步骤 08：转码任务投递

> 分期：Phase 2 前半。  
> 目标：commit 成功后写 `media_task`、发 RabbitMQ、媒资进入 `PROCESSING`。Worker 仍不消费。  
> 上一篇：[媒资查询](./07-媒资查询.md)　下一篇：[Worker 转码闭环](./09-Worker转码闭环.md)

## 本步要做什么

把「确认上传」与「任务流 Procedure」接上。对应云侧自动转码 + 截封面任务，只是执行方换成自建 Worker。

## 消息体

建议 JSON：

```json
{
  "fileId": "f7c2a1b0e9d84f6a",
  "mediaId": 1,
  "objectKey": "raw/f7c2a1b0e9d84f6a/source.mp4",
  "taskId": 10
}
```

交换机 / 队列命名示例：`vod.procedure` 队列，直连交换机即可。

## 处理流程（补全 commit）

在 `POST /vod/medias` 成功 Head 之后：

1. 若 `status` 已是 `PROCESSED`：直接返回（幂等，测试 T2）
2. 若已有未完成 `media_task`：不重复插入、不重复发消息（或发消息但 Worker 幂等，二选一，首期推荐 **不重复建任务**）
3. 插入 `media_task`：`type=PROCEDURE`，`status=PENDING`，`attempt=0`
4. 发送 MQ
5. `media.status = PROCESSING(2)`
6. 返回 DTO

发送 MQ 失败：任务标 FAILED 或保持 PENDING 并让接口 5xx，避免「库已 PROCESSING 但无人消费」。推荐：本地事务写库后发 MQ；发失败则接口失败并打日志，可用定时补偿（二期）。

## 操作步骤

### 1. `vod-api` 引入 Spring AMQP

配置 `RABBITMQ_HOST=rabbitmq` 等。声明 Queue（或与 worker 共用一份配置类）。

### 2. `MediaTask` 仓储

按 `file_id` 查进行中任务。

### 3. 改造 commit

按上面流程把第 06 步的 `UPLOADED` 延伸到 `PROCESSING`。  
若希望列表里短暂看到「已上传」，可先写 `UPLOADED` 再立刻改 `PROCESSING`，对外几乎无差别。

### 4. 验证

1. 完整走上传 + commit
2. 查 `media.status=2`
3. 查 `media_task` 一行 `PENDING`
4. RabbitMQ 管理台 Queues 里消息 Ready ≥ 1（因 Worker 尚未消费会堆积，这是预期）

## 完成标准

- [ ] commit 后任务行存在且 MQ 有消息
- [ ] 已 PROCESSED 的重复 commit 不建新任务
- [ ] Worker 仍可以未实现

## 本步不做

- 不下载、不跑 FFmpeg
- 不写 Webhook（第 13 步）
