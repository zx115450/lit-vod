# 08：目标机初始化与部署

> 目标：演示机首次落盘 Compose，之后只需 CI 滚动 `vod-api` / `vod-worker`。  
> 上一篇：[编写 `.gitlab-ci.yml`](./07-编写gitlab-ci.yml.md)　下一篇：[验证、验收与回滚](./09-验证验收与回滚.md)

## 本步要做什么

一次性把基础设施和目录准备好；日常 CD 只更新两个应用容器。

## 一次性初始化

```bash
# 在演示机
sudo mkdir -p /opt/lite-vod
# 拷贝 compose、nginx、sql、.env.example → .env
cd /opt/lite-vod
docker login harbor.example.com
# 首次可用 latest 或指定 sha
export IMAGE_TAG=xxxxxxxx
docker compose pull
docker compose up -d
curl -fsS http://127.0.0.1:8080/vod/health
```

## 目录与职责

| 内容 | 说明 |
| --- | --- |
| MySQL / RabbitMQ / MinIO / Nginx | 可与 api/worker 同一份 compose **常驻** |
| `vod-api` / `vod-worker` | CD 每次 `pull` + `up -d` 滚动 |
| `.env` | `VOD_PLAY_SECRET`、DB、MinIO、`IMAGE_TAG` 等 |

## 与本项目配置的衔接

| 项 | 做法 |
| --- | --- |
| `VOD_PLAY_SECRET` | 只在目标机 `.env`，不进镜像、不进 `.gitlab-ci.yml` |
| `play-sign.public-base` | 指向演示域名（Nginx 或 API 网关） |
| 健康检查 | 部署脚本末尾 `curl /vod/health`，失败则 Job 红 |
| SSH | CI 用户公钥已在 `authorized_keys`；`DEPLOY_PATH` 指向本目录 |

## CI 手动 Deploy 时发生的事

1. 写入 / 更新 `.env` 中的 `IMAGE_TAG=$CI_COMMIT_SHORT_SHA`
2. `docker login` Harbor
3. `docker compose pull vod-api vod-worker`
4. `docker compose up -d vod-api vod-worker`
5. `curl` 健康检查

## 完成标准

- [ ] `/opt/lite-vod`（或约定路径）已就绪，`.env` 含密钥与 `IMAGE_TAG`
- [ ] 首次 `compose up` 后 `/vod/health` 返回成功
- [ ] （建议）在 GitLab 手动跑通一次 `deploy_staging`

## 本步不做

- 不迁 K8s
- 不把演示机密钥回写进仓库
