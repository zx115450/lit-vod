# 09：验证、验收与回滚

> 目标：确认门禁有效、制品可发布、出问题能按 tag 回滚。  
> 上一篇：[目标机初始化与部署](./08-目标机初始化与部署.md)　下一篇：返回 [阅读说明](./00-阅读说明.md) 或进入 [增强与对接](../16-增强与对接天机学堂.md)

## 本步要做什么

按检查表验收整条链路，并演练一次回滚。

## 在 GitLab 验证

1. 开一个故意失败的 MR（改坏一个单测）→ Pipeline 红 → **无法合并**
2. 修好 → `test` 绿 → 可合并
3. `main` 上 `build_push` 成功，Harbor 能看到：
   - `vod-api:$sha`
   - `vod-worker:$sha`
4. 手动点 `deploy_staging` → 目标机容器换新 tag → `/vod/health` 200
5. 回滚：把 `.env` 的 `IMAGE_TAG` 改回旧 sha，再：

```bash
cd /opt/lite-vod
docker compose pull vod-api vod-worker
docker compose up -d vod-api vod-worker
curl -fsS http://127.0.0.1:8080/vod/health
```

## 完成标准（本目录全局）

- [ ] GitLab 可登录，至少一台 Runner online
- [ ] 存在可运行的 `.gitlab-ci.yml`
- [ ] MR / push 会自动执行 `mvn test`
- [ ] `main` 开启 Protected Branch + Pipelines must succeed
- [ ] CI 能 `docker build` 并推送 api / worker 到 Harbor（tag 含 commit sha）
- [ ] 手动 Deploy 后演示机 `compose pull && up -d` 成功，健康检查通过
- [ ] 仓库与 CI 配置中无真实数据库密码、`VOD_PLAY_SECRET`、Harbor / SSH 明文
- [ ] 能用自己的话讲清：CI 与 CD、Harbor 角色、失败如何阻断上线、如何按 tag 回滚

## 常见问题

| 现象 | 排查 |
| --- | --- |
| `COPY target/*.jar` 失败 | CI 未先 `mvn package`，或 `docker build` context 不是含 `target` 的模块目录 |
| `docker login` 失败 | Harbor 项目权限、机器人账号、HTTP 不安全仓库需 daemon 配置 |
| DinD 权限 / TLS 报错 | 按 GitLab 文档配置 `DOCKER_TLS_CERTDIR`，或改用 Kaniko / 宿主机 Docker Socket |
| SSH 超时 | Runner 到演示机网络、安全组、`ssh-keyscan`、密钥格式（OpenSSH） |
| 健康检查失败 | 容器未就绪、端口未映射、依赖 MySQL 未 healthy |

## 本目录不做

- 不上 K8s / Helm / Argo CD / Istio
- 不并行再搭 Jenkins（先精通 GitLab CI 一条链路）
- 不做占满 Runner 的全量 E2E
- 不替代步骤 15 的用例设计；流水线只是执行器

## 面试怎么说（可选）

> 点播 Demo 用 Docker Compose 部署。GitLab CI 在 MR 上跑 Maven 单测，合入 main 后构建 api/worker 镜像并推 Harbor；演示环境通过 SSH 执行 compose pull/up，用 commit sha 做不可变 tag，出问题改 tag 回滚。密钥走 CI Variables 与机器 `.env`。业务上是上传转码与 HMAC 播放鉴权，工程上补了质量门禁与制品发布。
