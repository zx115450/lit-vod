# CI 与 CD 流水线：分步阅读说明

> 把 [步骤 17 总览](../17-CI与CD流水线.md) 拆成「一步一个文档」。  
> 选型：GitLab → GitLab CI → Harbor → SSH + Docker Compose（不上 K8s）。  
> 建议在 [测试用例落地](../15-测试用例落地.md) 通过后再做。

## 使用方式

1. 先读本目录 `01`，搞清 CI / CD / Harbor 各干什么
2. 无现成 GitLab 时先做 `02`（自建或改用 gitlab.com）；已有实例可只核验 Runner
3. 再按 `03` → `09` 顺序做；每步末尾有「完成标准」
4. 密钥、密码、`VOD_PLAY_SECRET` 永不写进 yaml / 镜像 / 仓库
5. 业务增强（步骤 16）另开分支；本目录只护 `main` 的工程化链路

## 总览链路

```text
（可选）部署 GitLab CE + 注册 Runner
                      │
feature/* ──MR──► GitLab CI: test
                      │ 绿
                      ▼
                 package + docker build
                      │
                      ▼
                 docker push → Harbor
                      │
                      ▼（仅 main / 手动 job）
                 SSH 演示机
                      │
                      ▼
           compose pull && up -d
                      │
                      ▼
              curl /vod/health
```

## 原则

- **一步一验收**：勾完完成标准再进下一步
- **密钥不入库**：走 GitLab CI/CD Variables 与目标机 `.env`
- **本机开发与演示分离**：本地可继续 `build:`；演示机用 Harbor `image:`
- **不上 K8s**：与现有 `lite-vod/docker-compose.yml` 对齐即可
- **GitLab 与业务机分离**：自建 CE 吃内存，尽量不要和 lite-vod 演示机挤在一台低配机

## 全局完成标准

- [ ] GitLab 可登录，且至少一台 Runner online（自建或公司实例）
- [ ] 存在可运行的 `.gitlab-ci.yml`
- [ ] MR / push 会自动执行 `mvn test`
- [ ] `main` 开启 Protected Branch + Pipelines must succeed
- [ ] CI 能构建并推送 `vod-api` / `vod-worker` 到 Harbor（tag 含 commit sha）
- [ ] 手动 Deploy 后演示机健康检查通过
- [ ] 仓库与 CI 配置中无真实密码与 `VOD_PLAY_SECRET`
