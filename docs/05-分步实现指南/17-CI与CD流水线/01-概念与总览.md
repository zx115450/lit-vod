# 01：概念与总览

> 目标：用自己的话讲清 CI、CD、Harbor、Compose 在本项目中的角色。  
> 上一篇：[阅读说明](./00-阅读说明.md)　下一篇：[部署 GitLab 与 Runner](./02-部署GitLab与Runner.md)

## 本步要做什么

先建立心智模型，再动手配 GitLab / Harbor。本仓库已有 `Dockerfile` 与 `docker-compose.yml`，流水线是「挂上去」，不是重写部署方案。

## 四个概念

| 概念 | 含义 | 本项目落点 |
| --- | --- | --- |
| **CI**（持续集成） | 每次改代码自动编译/测试，失败阻断合并 | MR / push 跑 `mvn test` |
| **制品** | 可部署的二进制或镜像 | `mvn package` + `docker build` → Harbor |
| **CD**（持续部署） | 把制品装到运行环境 | SSH 演示机：`compose pull && up -d` |
| **运行** | 进程怎么跑 | 现有 Docker Compose；**不上 K8s** |

## 为何放在步骤 15 之后

- 步骤 15 把单测 / T1～T8 稳住，CI 才有「绿」的意义
- 步骤 16 是业务增强，宜独立分支；流水线先护住 `main`
- 便于简历表述「质量门禁 + 制品发布 + 按 tag 回滚」

## 本步选型（国内、无 K8s）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 代码托管 | **GitLab** | 私有化常见；可自建 CE（见 [02](./02-部署GitLab与Runner.md)）或用公司实例 |
| CI | **GitLab CI** + **Runner** | 仓库根目录 `.gitlab-ci.yml`；无 Runner 则 Job 不跑 |
| 镜像仓库 | **Harbor** | 项目隔离、权限、可开扫描 |
| 部署 | **Compose + SSH** | 与 `lite-vod/docker-compose.yml` 对齐 |
| 密钥 | CI/CD Variables（Masked） | 永不写进 yaml / 镜像层 |

对照：若公开课仓库在 GitHub，可换成 Actions + GHCR；概念仍是「触发 → 测 → 构建 → 推仓 → SSH 部署」。无现成 GitLab 时，下一步先部署 CE 并注册 Runner。

## 分支与合并约定

```text
feature/*  → MR → CI test 绿 → 合入 main
main       → build_push →（手动）deploy_staging
```

禁止：跳过 CI 强推 `main`；禁止把 Harbor / SSH 密码写进 yaml 明文。

## 完成标准

- [ ] 能口述：CI 与 CD 分别做什么
- [ ] 知道 Harbor 存的是镜像、Compose 负责拉起容器
- [ ] 知道失败单测应阻断合入 `main`
