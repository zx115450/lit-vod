# 03：仓库与分支保护

> 目标：代码进 GitLab，`main` 只能走 MR，且流水线不过不能合。  
> 上一篇：[部署 GitLab 与 Runner](./02-部署GitLab与Runner.md)　下一篇：[准备 Harbor](./04-准备Harbor.md)

## 本步要做什么

搭好「合并门禁」的仓库侧规则。没有 Protected Branch，后面的 CI 红灯也拦不住直接 push。

## 操作步骤

前提：GitLab 已可登录，且有可用 Runner（见 [02-部署 GitLab 与 Runner](./02-部署GitLab与Runner.md)）。

1. 将本仓库推到 GitLab（路径示例：`group/lite-vod`，或 monorepo 含 `lite-vod/`）
2. Settings → Repository → **Protected branches**：保护 `main`
   - Allowed to merge：Maintainers（或按团队）
   - Allowed to push：**No one**（强制走 MR）
3. Settings → Merge requests：勾选 **Pipelines must succeed**
4. 确认 `.env`、真实密码、`VOD_PLAY_SECRET` **未进仓库**（检查 `.gitignore`）

## 名词对照

| 术语 | 含义 |
| --- | --- |
| **MR**（Merge Request） | 申请把功能分支合进 `main`；GitHub 叫 PR |
| **Protected Branch** | 受保护分支：禁止直接 push，只能 MR 合并 |
| **Pipelines must succeed** | CI 失败则无法点 Merge |

## 建议工作流

```text
git checkout -b feature/xxx
# 改代码、本地 mvn test
git push -u origin feature/xxx
# 在 GitLab 开 MR → 等 Pipeline → 绿了再 Merge
```

## 完成标准

- [ ] 仓库已在 GitLab 可访问
- [ ] `main` 已 Protected，Allowed to push = No one
- [ ] 已勾选 Pipelines must succeed
- [ ] 仓库中无明文密钥与 `.env` 真值

## 本步不做

- 还不要求 Pipeline 真的跑通（yaml 在步骤 07）
- 不配置 Harbor / 演示机
