# 步骤 10：播放签名签发

> 分期：Phase 3。  
> 目标：实现 `GET /vod/signature/play`，按 HMAC-SHA256 签发带 `e`、`exper`、`sign` 的播放 URL。  
> 上一篇：[Worker 转码闭环](./09-Worker转码闭环.md)　下一篇：[播放网关验签](./11-播放网关验签.md)

## 本步要做什么

VOD 内核只负责签发可播放地址，**不负责课表**。对接天机时由 `tj-media` 先鉴权再调本接口。

首期采用实现文档 8.1：**HMAC 签名 URL**（hls.js 更省事）。JWT 为备选，本步不做。

## 接口契约

- `GET /vod/signature/play?fileId=&exper=`
- `fileId` 必填；`exper` 可选（试看秒数，没有则 0）

仅当 `media.status=PROCESSED` 才签发，否则 4xx。

响应：

```json
{
  "fileId": "f7c2a1b0e9d84f6a",
  "playUrl": "http://localhost/hls/f7c2a1b0e9d84f6a/index.m3u8?sign=...&e=...&exper=300",
  "signature": "与 sign 相同或省略"
}
```

`playUrl` 的 Host 用配置项 `VOD_PLAY_PUBLIC_BASE`（如 `http://localhost`），指向第 11 步的 Nginx。

## 签名算法

待签名字符串：

```text
path={uriPath}&e={expireEpoch}&exper={experSeconds|0}
```

示例：

```text
path=/hls/f7c2a1b0e9d84f6a/index.m3u8&e=1710003600&exper=300
```

```text
sign = Hex(HMAC_SHA256(secret, 待签名字符串))
```

完整 URL：

```text
/hls/{fileId}/index.m3u8?e=...&exper=...&sign=...
```

约定：

- `uriPath` 必须是规范路径，无查询串，建议小写 hex 的 `fileId` 与库中一致
- `secret` 来自 `VOD_PLAY_SECRET`，与 MinIO 密码分开
- TTL 建议 1～2 小时（配置化）
- 十六进制大小写全局统一（建议小写），网关必须同样规则

试看首期：文档默认 L0（短 TTL）或 L1（网关记起播时间）。本步把 `exper` 写入 URL 即可；L1 在第 11 步实现或明确只做 L0。

## 操作步骤

1. 抽取 `PlaySignService.sign(path, expireAt, exper)` 与 `verify(...)`（verify 给网关或第 11 步的 auth 服务复用）
2. Controller 组装 `playUrl`
3. 单元测试：固定 secret + 固定输入 → 固定 hex；过期字段参与字符串

## 验证

- PROCESSED 的 fileId 能拿到 URL
- UPLOADING 的 fileId 拒绝签发
- 手工改 secret 后 sign 应变

浏览器播放放到第 12 步；本步用单测 + 看 JSON 即可。
