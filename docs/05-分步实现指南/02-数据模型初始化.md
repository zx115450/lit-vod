# 步骤 02：数据模型初始化

> 分期：Phase 0。  
> 目标：在 MySQL 中建好 `media`、`media_task`，并理解状态机。  
> 上一篇：[环境搭建](./01-环境搭建.md)　下一篇：[工程骨架](./03-工程骨架.md)

## 本步要做什么

把实现文档第五章落成仓库根目录 `sql/schema.sql`，同步到 Compose 的 `sql/` 挂载目录后初始化库，或手动执行一次。

## 前置条件

- 步骤 01 完成，MySQL 已启动
- 库名与 `.env` 中 `MYSQL_DATABASE` 一致（建议 `lite_vod`）

## 表设计要点

### `media`

对外主键概念是 `file_id`（UUID，对齐腾讯 `fileId`），库内可用自增 `id`。

必填字段：`file_id`、`object_key`、`status`、时间戳。  
处理完成后才填：`media_url`、`cover_url`、`duration`。

### `media_task`

一条媒资一次 Procedure 可对应一条任务（`type=PROCEDURE`），或拆成 `TRANSCODE` / `COVER`。首期建议 **一条 PROCEDURE**，实现简单。

### 状态机（`media.status`）

```text
UPLOADING(0) → UPLOADED(1) → PROCESSING(2) → PROCESSED(3)
                                    └────────→ FAILED(4)
```

建议用 `tinyint` 存数字，代码里用枚举映射。

## 操作步骤

### 1. 编写 `sql/schema.sql`

包含：

- `CREATE DATABASE` 可省略（Compose 已建库）
- `media`、`media_task` 建表语句
- `file_id` 唯一索引
- `media_task.media_id` 索引

字段类型、长度与实现文档 5.1、5.2 节对齐。

### 2. 执行脚本

若 Compose 已用空 `schema.sql` 初始化过库，改文件后 **不会自动重跑**。任选：

```bash
# 方式 A：进容器执行
docker compose exec mysql mysql -uvod -p lite_vod < /docker-entrypoint-initdb.d/schema.sql

# 方式 B：删 volume 后重建（会清空数据）
docker compose down -v
docker compose up -d
```

### 3. 核对

```sql
SHOW TABLES;
DESC media;
DESC media_task;
```
