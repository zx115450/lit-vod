# Lite VOD 核心架构图

> 与 [实现文档](./04-轻量版云点播-Lite-VOD-实现文档.md) 第二章、[前置知识](./03-点播与对象存储-前置知识.md) 第十一章对齐。  
> 在 Cursor / VS Code 中打开预览即可渲染 Mermaid。

---

## 1. 一句话

**字节走 MinIO，状态走 MySQL，任务走 RabbitMQ，播放走 Nginx 验签反代。**  
`vod-api` 不经手文件流；`vod-worker` 不对外提供页面。

---

```mermaid

  end

  subgraph biz["业务域（天机学堂，可后接）"]
    tj["tj-media<br/>课表鉴权 / 试看 / 小节绑定"]
  end

  subgraph lite["Lite VOD"]
    api["vod-api<br/>Spring Boot<br/>凭证 · 媒资 · 签名 · 事件"]
    worker["vod-worker<br/>FFmpeg<br/>下载 · 转码 · 回传"]
    gw["Nginx<br/>校验 sign/e<br/>反代 HLS"]
  end

  subgraph data["数据与中间件"]
    mysql[("MySQL<br/>media / media_task")]
    mq["RabbitMQ<br/>转码任务"]
    minio[("MinIO bucket: vod<br/>raw / hls / cover")]
  end

  admin -->|"1 JSON 凭证"| api
  admin -->|"2 PUT 原片"| minio
  admin -->|"3 commit JSON"| api
  api --> mysql
  api -->|"4 投递任务"| mq
  mq --> worker
  worker -->|"5 读原片"| minio
  worker -->|"6 写 HLS+封面"| minio
  worker --> mysql

  player -->|"A 要播放地址"| tj
  tj -->|"B 鉴权通过后"| api
  api -->|"C 签名 playUrl"| player
  player -->|"D 拉 m3u8/ts"| gw
  gw -->|"E 验签通过"| minio
```

首期演示可不接 `tj-media`：播放器直接调 `vod-api` 申请签名。

## 3. 职责切分

```mermaid
flowchart LR
  subgraph vod["Lite VOD 负责：能播"]
    s1["存原片"]
    s2["转码切片"]
    s3["签发播放 URL"]
  end

  subgraph course["业务负责：该不该播"]
    b1["sectionId → fileId"]
    b2["课表 / 登录"]
    b3["试看策略"]
  end

  course -->|"只传 fileId + exper"| vod
```

| 组件 | 做什么 | 不做什么 |
| --- | --- | --- |
| vod-api | 预签名、落库、发 MQ、播放 HMAC、查询删除 | 收大文件、跑 FFmpeg |
| vod-worker | 消费队列、转码、回写状态 | 对外 HTTP 业务接口 |
| MinIO | 存对象 | 鉴权课表、改媒资状态 |
| MySQL | 媒资与任务元数据 | 存视频二进制 |
| RabbitMQ | 解耦 API 与转码 | 存文件 |
| Nginx | 验签后反代 `/hls/` | 生成 fileId、转码 |

## 4. 上传与转码时序

```mermaid
sequenceDiagram
  actor Admin as 管理端
  participant API as vod-api
  participant DB as MySQL
  participant S3 as MinIO
  participant MQ as RabbitMQ
  participant W as vod-worker

  Admin->>API: GET /vod/signature/upload
  API->>DB: 插入 media status=UPLOADING
  API-->>Admin: fileId + uploadUrl
  Admin->>S3: PUT raw/{fileId}/source.mp4
  Admin->>API: POST /vod/medias
  API->>S3: HeadObject 确认存在
  API->>DB: UPLOADED → 建 task → PROCESSING
  API->>MQ: 消息 {fileId, objectKey}
  API-->>Admin: MediaDTO 处理中

  MQ->>W: 投递
  W->>DB: task=RUNNING
  W->>S3: 下载原片
  W->>W: FFmpeg HLS + 封面
  W->>S3: 上传 hls/ 与 cover/
  W->>DB: media=PROCESSED
  opt 可选
    W-->>API: Webhook / 写事件
  end
```

对象路径：

```text
vod/raw/{fileId}/source.mp4
vod/hls/{fileId}/index.m3u8
vod/hls/{fileId}/segment_xxx.ts
vod/cover/{fileId}.jpg
```

## 5. 播放时序（含验签）

```mermaid
sequenceDiagram
  actor User as 学员端
  participant Biz as tj-media（可选）
  participant API as vod-api
  participant GW as Nginx
  participant S3 as MinIO

  User->>Biz: 要看某小节
  Biz->>Biz: 课表 / 试看
  Biz->>API: GET /vod/signature/play?fileId&exper
  API-->>Biz: playUrl?e&exper&sign
  Biz-->>User: playUrl
  User->>GW: GET /hls/{fileId}/index.m3u8?...
  GW->>GW: HMAC 校验 e / sign
  alt 过期或篡改
    GW-->>User: 403
  else 通过
    GW->>S3: GET vod/hls/{fileId}/...
    S3-->>GW: m3u8 / ts
    GW-->>User: 200
  end
```

原则：MinIO 不对公网匿名读；学员只打播放域名。

## 6. 状态与数据落点

```mermaid
stateDiagram-v2
  [*] --> UPLOADING: 签发上传凭证
  UPLOADING --> UPLOADED: HeadObject 成功
  UPLOADED --> PROCESSING: 投递 MQ
  PROCESSING --> PROCESSED: 转码成功
  PROCESSING --> FAILED: 转码失败
```

```mermaid
flowchart TB
  subgraph mysql["MySQL"]
    m["media：file_id / status / duration / 路径"]
    t["media_task：RUNNING / SUCCESS / FAILED"]
  end
  subgraph minio["MinIO"]
    r["原片字节"]
    h["HLS 切片字节"]
    c["封面字节"]
  end
  m -.->|"只存 key，不存文件"| r
  m -.-> h
  m -.-> c
```

## 7. 部署拓扑（Compose）

```mermaid
flowchart TB
  browser["浏览器 :80 / :8080"]
  nginx["nginx:alpine :80"]
  api["vod-api :8080"]
  worker["vod-worker 无对外端口"]
  mysql["mysql:8 :3306"]
  rmq["rabbitmq :5672 / 15672"]
  minio["minio :9000 / 控制台 9001"]

  browser --> nginx
  browser --> api
  nginx -->|"auth_request 可选"| api
  nginx --> minio
  api --> mysql
  api --> rmq
  api --> minio
  worker --> rmq
  worker --> mysql
  worker --> minio
```

Worker 与 API 分容器，避免 FFmpeg 拖垮接口。
