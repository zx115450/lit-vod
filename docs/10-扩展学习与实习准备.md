## 一、和本项目的关系

Lite VOD 覆盖的是云点播「常用子集」：

```text
申请上传凭证 → 直传对象存储 → commit 确认
    → MQ 投递 → Worker + FFmpeg 转 HLS
    → 播放签名 → 网关验签 → hls.js 播放
```

扩展学习分三层：

| 层 | 目标 |
| --- | --- |
| **项目内做深** | 把 `01～15` 做完，能独立排障 |
| **知识补齐** | HTTP 鉴权、S3、MQ、视频基础、FFmpeg |
| **方向延伸** | 分片续传、多码率、CDN、直播 / RTC（按兴趣） |

原则：**先闭环，再扩展**。二期能力见步骤 [16](./05-分步实现指南/16-增强与对接天机学堂.md)，不必提前做。

## 二、实习方向怎么选

### 2.1 推荐优先级（学生实习）

| 优先级 | 方向 | 适合原因 | 注意 |
| --- | --- | --- | --- |
| 高 | 在线教育 / 知识付费 | 录播、试看、播放鉴权与本项目最像，易接到完整需求 | 技术品牌不如大厂硬 |
| 高 | 中型音视频云 / 媒体中台 | 上传、转码、播放链路完整 | 看清是否真做媒体 |
| 中 | 云厂商音视频（腾讯云 / 阿里云 / 火山） | 含金量高，对标 VOD 文档 | 实习常只做一块，面试前问清组 |
| 中 | B 站 / 短视频相关组 | 转码与播放体量大 | 竞争强，基础要更扎实 |
| 低 | 纯业务 CRUD「挂个视频 URL」 | 简历难写出点播深度 | 除非没有更好选择 |

**务实结论：** 实习先求「闭环经历」，再求「大厂牌子」。教育与中小音视频云，性价比往往更高。

### 2.2 国内可关注的公司类型

- **云与音视频基建**：腾讯云 VOD、阿里云视频点播、火山引擎、网易云信、声网、即构等
- **重度视频业务**：字节、B 站、快手、腾讯视频 / 视频号相关、爱奇艺等
- **教育与 ToB**：好未来、猿辅导、作业帮、有道、得到、小鹅通，以及私有云点播类厂商

投递时用关键词：`音视频`、`流媒体`、`多媒体`、`点播`、`转码`、`RTC`、`媒体中台`。

### 2.3 入组前建议问清的问题

1. 组内是否有上传 / 转码 / 播放 / CDN 中的真实链路
2. 实习同学能否独立跟一个小需求到上线或提测
3. 技术栈是否包含对象存储、FFmpeg / 转码服务、MQ 之一

### 3.2 必须补齐（实习面试高频）

| 主题 | 要能讲清什么 | 建议学法 |
| --- | --- | --- |
| HTTP 与鉴权 | 预签名 URL、HMAC、过期时间 `e`、防盗链；JWT 与签名 URL 的取舍 | 对照步骤 05、10、11，自己推一遍签名串 |
| 对象存储 S3 | Bucket、ObjectKey、`PUT` / `HEAD`、预签名、为何不经业务机传大文件 | 读前置知识 + 动手用 `mc` / SDK |
| 异步与 MQ | 为何转码不能同步；幂等、重试、死信；重复 commit 不重复建任务 | 对照 `media` / `media_task` 状态机 |
| 视频与 HLS | 容器 vs 编码；`m3u8` + `.ts`；为何网页少直接播原片 mp4 | 看自己转出来的目录结构 |
| FFmpeg / ffprobe | 转 HLS、截封面、读 `duration`；失败时看日志 | Worker 步骤 + [Java 调用命令行](./Java-ProcessBuilder.md) |
| 后端通用 | MySQL 索引与事务、线程池、异常与超时 | 刷一小套后端面试题即可 |
| CI/CD | MR 触发测试、质量门禁、Harbor 镜像、CI Variables、Compose 部署回滚 | 按步骤 17 用本仓库加 GitLab CI + Harbor |

### 3.3 加分项（有余力）

| 主题 | 用途 |
| --- | --- |
| Multipart 分片与断点续传 | 大文件二期；说明「能力在 S3，编排在客户端 + 服务端」 |
| CDN、Range、缓存 | 播放加速与拖进度 |
| 多码率 / ABR | 自适应播放 |
| 试看 L0 / L1 / L2 | 教育场景高频 |
| 直播 vs 点播、RTC 皮毛 | 拓宽岗位面（声网 / 云信向） |
| `hls.js` 与简单演示页 | 端到端自测，面试可演示 |

### 3.4 实习前不必深挖

- 自研编码器、复杂 DRM、WebRTC 底层实现
- 分布式存储引擎源码
- 与点播无关的大型推荐系统

## 四、建议学习节奏

按「已有 Lite VOD 仓库」假设每周能投入较完整时间：

### 阶段 A：闭环（优先，约 1～2 周量）

1. 按分步指南做到演示页可播放
2. 画一张自己的架构图（可对照 [核心架构图](./06-核心架构图.md)）
3. 整理状态机：`UPLOADING → … → PROCESSED / FAILED`
4. 准备 3 个排障故事（例如：直传成功但未 commit、镜像拉取失败、验签 403）

### 阶段 B：原理补课（约 1 周）

1. 手写说明：为何直传 MinIO、为何要 commit、HeadObject 防什么
2. 手写说明：MQ 消息丢了 / 重复了怎么办（结合 `media_task.attempt`）
3. 弄清一条播放 URL 里 `sign`、`e`、`exper` 各干什么
4. 后端基础：事务、唯一索引（`file_id`）、接口幂等
5. 按 [步骤 17](./05-分步实现指南/17-CI与CD流水线.md) 加 GitLab CI（至少 `mvn test`，建议推 Harbor）

### 阶段 C：加分与投递（持续）

1. 选做步骤 16 之一：分片上传或事件回调；或把步骤 17 扩到镜像构建 / 演示部署
2. 对照 [腾讯云 VOD 总览](./08-腾讯云点播-VOD-开发文档总览.md)，做一张「云 vs Lite」对照表
3. 改简历项目描述，开始投递；根据目标公司补 CDN 或 RTC 皮毛

## 六、面试可讲的项目叙事

### 6.1 一句话

独立实现对齐腾讯云 VOD 常用子集的轻量点播：预签名直传 MinIO、异步 FFmpeg 转 HLS、播放 URL 鉴权。

### 6.2 建议展开的 5 个点

1. **为何不经 Java 收大文件**（带宽、扩展、与云厂商同构）
2. **状态机与 `media_task`**（媒资状态 vs 任务状态）
3. **commit + HeadObject**（直传成功如何被服务端确认）
4. **MQ + Worker**（CPU 密集与 API 分离、重试与幂等）
5. **播放鉴权**（签名字段、网关验签、防盗链）

### 6.3 常被追问

| 问题 | 答法方向 |
| --- | --- |
| 上传中服务宕机了？ | `UPLOADING` 可超时清理；对象未 commit 不建任务 |
| 重复点击「确认上传」？ | 按 `file_id` 幂等；已 `PROCESSED` 直接返回 |
| 转码消息丢了？ | 任务表可对账；失败重试与死信；监控 `PENDING` 过久 |
| 为何选 HLS？ | 网页友好、可切片鉴权、弱网与 CDN 成熟 |
| 和腾讯云差在哪？ | 无多码率云处理、无全球 CDN、事件与套件不如云完整；首期子集可私有化演示 |

## 八、完成自评

扩展学习不设「必须全部学完」。实习投递前，建议至少满足：

- [ ] Lite VOD 主路径可演示（上传 → 处理完成 → 可播放）
- [ ] 能不看稿讲清架构与状态机（约 5～8 分钟）
- [ ] 必须补齐表（第三节 3.2）每一项都能举本项目的例子
- [ ] （建议）已按步骤 17 挂上 CI，能说明质量门禁与镜像制品
- [ ] 简历项目描述已改成「能力表述」，而非只罗列框架名
- [ ] 明确第一志愿实习方向（教育 / 云音视频 / 视频平台之一）
