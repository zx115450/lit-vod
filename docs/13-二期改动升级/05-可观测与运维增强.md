# 05：可观测与运维增强

> 目标：为二期上线提供最小可用指标与排查手段，不引入过重 APM 也可先做日志 + 计数。  
> 上一篇：[对接天机学堂](./04-对接天机学堂.md)　下一篇：[改造清单与兼容策略](./06-改造清单与兼容策略.md)

## 1. 建议指标

| 指标 | 来源 | 用途 |
| --- | --- | --- |
| 上传凭证发放次数 / 失败 | vod-api | 异常申请突增 |
| commit 成功 / 4xx | vod-api | 直传未完成占比 |
| 转码成功 / 失败 / 耗时 | media_task `finished_at - created_at` | Worker 容量 |
| 转码重试次数分布 | `attempt` | 毒消息与坏文件 |
| 播放验签 403 率 | 网关 / Nginx 日志 | 盗链或时钟问题 |
| 回调成功 / 放弃 | CallbackNotifier 日志 | 业务侧可达性 |
| 分片 Complete / Abort | 二期 API | 残留分片 |

## 2. 落地方式（由易到难）

1. **结构化日志**：fileId、taskId、耗时、status 固定字段，便于 grep
2. **Micrometer + Actuator**（可选）：`/actuator/prometheus`
3. **定期 SQL**：扫 `PROCESSING` 过久、`PENDING` 过久任务

## 3. 告警建议（演示环境可人工看）

- 转码失败率 > 阈值阈值
- `PENDING` 超过 30 分钟未消费
- 播放 5xx / 网关 MinIO 502 升高
- 回调连续失败

## 4. 验收

- [ ] 能从日志或指标回答：昨天转码平均多久、失败多少
- [ ] 能发现卡住的 PROCESSING 任务
- [ ] 密钥与指标端点（若暴露）有访问控制
