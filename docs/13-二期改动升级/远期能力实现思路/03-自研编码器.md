# 03：自研编码器 — 实现思路

> 对应边界：二期不做自研编码器。  
> 现网转码 = **调用 FFmpeg / ffprobe 进程**（`ProcessBuilder`），不维护编码算法本身。

## 1. 「编码器」在业务里指什么

| 层次 | 含义 | 现网做法 |
| --- | --- | --- |
| **编码算法** | H.264/H.265 怎么压像素 | 使用 x264/x265（FFmpeg 链入） |
| **转码产品** | 多档、封面、封装 HLS | Worker 编排命令与上传 |
| **自研编码器** | 自己实现或深度魔改压缩核 | **不做** |

多数业务说的「转码服务」其实是**编排层**；真正自研编码核属于多媒体基础研发。

## 2. 现网已足够的部分（应保留）

```text
下载原片 → ffprobe 时长
  → ffmpeg 转 HLS / 截封面
  → 上传 MinIO → 更新 media / media_task
  → 失败重试与毒消息保护
```

业务价值在：状态机、幂等、对象键、与播放鉴权闭环。  
换「自研编码器」不会自动提高这些能力。

## 3. 若单独立项「自研 / 深度定制」，可能指哪几档

由浅到深（成本递增）：

| 档位 | 内容 | 是否还算「本仓库业务」 |
| --- | --- | --- |
| A. 参数与模板体系 | 多 preset、按片源选 crf/码率 | 是，属 Worker 增强 |
| B. 插件化滤镜 | 水印、片头片尾、HDR→SDR | 多为 FFmpeg 滤镜图，仍可进程调用 |
| C. 替换内核 | 换 NVENC / QSV / 云转码 API | 适配层，可不自研算法 |
| D. 自研码控 / 新标准实现 | 写编码器、追标准、追质量 | **专项基础研发，另开仓库** |

二期「不要做自研编码器」主要排除 **D**，以及把 C 做成无云无硬件的纯自研。

## 4. 实现思路（若真做 D）

不建议在 Lite VOD 进程内嵌：

```text
独立 codec 团队 / 仓库
  → 输出可执行文件或库（类似 ffmpeg CLI）
  → Lite VOD Worker 只改 Command 列表与产物约定
```

验收应对齐：PSNR/SSIM、速度、专利与许可证，而不是「接口能 200」。

## 5. 更务实的增强（可归二期或三期，但不是自研编码器）

- GPU 加速转码（NVENC）降耗时  
- 多码率 ABR（见 [02-多码率](../02-多码率ABR.md)）  
- 模板化转码参数、按时长/分辨率分流  
- 坏片检测与更细的 `error_msg`  

## 6. 一句话边界

> Lite VOD 做**转码编排与媒资闭环**；编码核用 FFmpeg/硬件/云；自研编码器单独立项、独立团队，不塞进本 Demo 二期。
