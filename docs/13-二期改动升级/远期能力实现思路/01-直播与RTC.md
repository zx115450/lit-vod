# 01：直播与 RTC — 实现思路

> 对应边界：二期不做直播 / RTC。  
> 现网 Lite VOD 只做**点播**（固定文件 → HLS）。直播与实时通信是另一条产品线。

## 1. 业务分别是什么

| 形态 | 用户感知 | 数据形态 | 延迟量级 |
| --- | --- | --- | --- |
| **点播（现网）** | 看已上传的课 | 文件 + m3u8 + ts | 秒级可接受 |
| **直播** | 看正在发生的课/活动 | 持续推流，清单不断刷新 | 数秒～十几秒 |
| **RTC** | 连麦、互动教室 | 端到端实时音视频 | 毫秒～两百毫秒级 |

不能把「直播」当成「点播转码加快一点」；协议、架构、运维都不同。

## 2. 直播实现思路（若单独立项）

### 2.1 典型链路

```text
主播端推流（RTMP / WebRTC 入库）
  → 收流 / 转协议（SRS、Nginx-RTMP、云直播）
  → 转码多码率（可选）
  → 分发：LL-HLS / HLS / HTTP-FLV / WebRTC
  → 播放器拉流
  → （可选）录制落盘 → 转成点播媒资进 Lite VOD
```

### 2.2 与 Lite VOD 的衔接点

- **录播回放**：直播结束后把成片 `commit` 进现有点播链路（最划算的组合）
- **鉴权**：直播 URL 仍可用短 TTL 签名；课权在业务服务校验后再向直播系统要播放地址
- **不要**：把 FFmpeg Worker 当直播转码主路径（批式任务模型不适合长连接推流）

### 2.3 技术选型方向（思路级）

| 组件 | 可选 |
| --- | --- |
| 开源收流 | SRS、MediaMTX |
| 云托管 | 腾讯云直播、阿里云直播 |
| 播放 | flv.js / mpegts.js / 原生 HLS |

### 2.4 工作量直觉

独立小型直播 Demo：周级～月级；要稳定、鉴权、录制回放打通：月级以上。

## 3. RTC 实现思路（若单独立项）

### 3.1 典型链路

```text
客户端采集 → 编码
  → 信令（进房、订阅、权限）
  → 媒体：WebRTC（UDP / SRTP）
  → SFU（选择性转发）或 MCU（混合）
  → 对端解码播放
```

### 3.2 与点播的差异

- 无「先转码再播」的媒资状态机；强调 **ICE / 弱网 / 丢包重传**
- 权限是「房间 + 角色」，不是 `fileId` + HMAC 文件签名
- 一般直接接 **声网 / 腾讯实时音视频 / LiveKit** 等，而不是自研 SFU

### 3.3 和 Lite VOD 的边界

- RTC 互动教室 ≠ Lite VOD
- 课后回放：云录制文件 → 再进 Lite VOD 点播

## 4. 不建议在本仓库硬做的原因

1. 与现有 MQ + 批式 FFmpeg 模型冲突  
2. 运维面（端口、UDP、NAT、带宽）远超 Compose Demo  
3. 面试与私有化演示的 ROI 低于把点播做深（分片 / ABR / L2）

## 5. 若必须写进架构图

单独画「直播子系统 / RTC 子系统」，只通过「录制文件 fileId」与 Lite VOD 虚线连接，避免画成同一个服务里的两个 Controller。
