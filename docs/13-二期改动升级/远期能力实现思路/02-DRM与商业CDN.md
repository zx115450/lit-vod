# 02：DRM 与商业 CDN — 实现思路

> 对应边界：二期不做 DRM、商业 CDN 调度。  
> 现网用网关 HMAC 防盗链 + 可选 Nginx；未接 Widevine/FairPlay，也未做全球调度。

## 1. 业务分别是什么

| 能力 | 要解决什么 | 现网近似物 |
| --- | --- | --- |
| **防盗链（已有）** | 无签名 / 过期 / 篡改 path 不能拉流 | `PlaySignService` + 网关 |
| **商业 CDN** | 就近缓存切片、抗带宽峰值、回源 MinIO | 单机 / 内网直出 |
| **DRM** | 即使下载了切片也无法在未授权设备解密播放 | 无（明文 H.264/AAC） |

防盗链 ≠ DRM：前者挡「随手拖走 URL」；后者挡「拿到密文文件也播不了」。

## 2. 商业 CDN 实现思路

### 2.1 典型接入

```text
播放器
  → CDN 边缘（*.cdn.example.com/hls/...）
  → 未命中回源到：播放网关或可签名的源站
  → 源站再读 MinIO
```

### 2.2 关键设计点

| 点 | 思路 |
| --- | --- |
| 缓存键 | 按 URL path；query 中的 `sign` 是否参与缓存要谨慎（通常签名不应进缓存键，或短 TTL） |
| 鉴权位置 | 边缘鉴权（CDN 函数 / 鉴权型 URL）或回源到现有网关验签 |
| 切片缓存 | `.ts` 长缓存；`m3u8` 短缓存或 no-store（点播可稍长） |
| 回源协议 | HTTPS；源站仍是 Lite VOD 网关，避免桶公钥匿名读 |
| 调度 | 厂商 Global Accelerator / 智能路由；自研成本极高 |

### 2.3 与现网改造关系

- 签发 `playUrl` 的 `publicBase` 改为 CDN 域名即可做「接入级」升级  
- 网关逻辑可保留；重点是缓存头与鉴权方案对齐 CDN 厂商文档  
- **不必**为了 CDN 重写转码链路

### 2.4 工作量直觉

接一家云 CDN + 改域名与缓存策略：天～周级。  
自建多机房调度：不建议作为学习项目目标。

## 3. DRM 实现思路

### 3.1 典型链路（Widevine / FairPlay / PlayReady）

```text
转码时：加密切片（如 AES-128 / SAMPLE-AES / CENC）
  → 清单带密钥地址或 license 指示
播放器：向 License Server 持用户票据换内容密钥
  → 解密播放
```

### 3.2 组件

| 组件 | 职责 |
| --- | --- |
| 打包加密 | 转码流水线增加 encryption（Shaka Packager、厂商 DRM 打包） |
| License Server | 校验用户/设备/权益后下发密钥 |
| 播放器 | EME（浏览器）或原生 DRM API |
| 密钥管理 | 与 `VOD_PLAY_SECRET` 完全不同体系，需 HSM / KMS |

### 3.3 和现网防盗链的关系

```text
现网：明文媒体 + URL 签名（防冒用链接）
DRM：密文媒体 + License（防解密与扩散）
```

可叠加：CDN + 签名 + DRM；成本与合规（设备证书、苹果 FairPlay 申请）显著上升。

### 3.4 不建议本仓库硬做的原因

1. 厂商合同、证书、设备兼容性周期长  
2. Worker 从「出清晰 HLS」变成「加密打包 + 密钥轮转」  
3. Demo / 私有化教学场景通常防盗链足够  

## 4. 立项时的最小路径建议

1. 先上 **CDN + 现有 HMAC**（性价比最高）  
2. 确有影视级防扩散需求再上 **托管 DRM**（买云 DRM，不自研 license）  
3. 避免自研 CDN 调度与自研 DRM 协议
